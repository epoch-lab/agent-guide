# MCP

`MCP`（Model Context Protocol）为模型访问工具和资源提供了标准接口。

你可以把它理解为模型运行时和外部系统之间的上下文与能力通道。

## 为什么重要

- 减少针对不同模型厂商重复写胶水代码。
- 明确模型可见数据与可调用能力的边界。
- 让能力组件在多个项目中复用和组合。

## 核心角色

- **客户端运行时**：从 Agent 运行时发起能力请求。
- **MCP Server**：按契约暴露资源、工具和提示能力。
- **模型层**：根据任务规划决定何时调用能力。

## 集成步骤

1. 定义能力面（resources、tools、prompts）。
2. 为每个端点设置最小权限范围。
3. 增加日志、trace ID、审计字段。
4. 同时验证正常输入与对抗输入。

## 风险与控制

| 风险 | 常见原因 | 控制策略 |
| --- | --- | --- |
| 数据过曝 | 资源暴露范围过宽 | 最小权限资源映射 |
| 不安全执行 | 缺少策略层约束 | 运行时护栏与确认机制 |
| 排障困难 | 可观测性不足 | 统一 trace 与结构化日志 |

## 团队规则

- 每个 MCP 能力必须有负责人和版本号。
- 每次接口变更都要同步更新调用示例。
- 新增高风险工具必须经过安全评审。
