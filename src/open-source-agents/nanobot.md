# Nanobot

Nanobot 常见于轻量化、可组合的 Agent 实验与业务接入场景。

它的价值通常不在于“大而全”，而在于“可快速拼装和验证”。

## 重点观察项

- 核心模块是否解耦，便于替换模型与工具后端。
- 是否支持最小可行链路快速上线。
- 在复杂任务场景下如何保持输出一致性。

## 架构阅读清单

### 模块边界

- 任务规划、执行器、状态管理是否独立。
- 能否按功能开启或关闭特定子模块。

### 扩展机制

- 新工具如何注册与鉴权。
- 新任务类型如何扩展而不改核心流程。

### 可靠性

- 是否内置超时、重试与降级策略。
- 出错时是否具备可追踪上下文。

## 迁移建议

- 用它做“单一业务流”的快速 PoC，再决定是否大规模引入。
- 把业务特有逻辑放到适配层，避免与框架核心耦合。
- 为每个自定义工具补齐契约测试。

## 验证计划

1. 先验证单工具链路稳定性。
2. 再验证多工具组合下的上下文一致性。
3. 最后评估在真实业务流量下的成本与延迟。
