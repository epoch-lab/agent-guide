# 工具编排

工具编排决定了 Agent 在真实场景中的稳定性上限。

核心不是“能调多少工具”，而是“复杂任务下还能否可控、可解释、可恢复”。

## 编排设计重点

- 任务拆解规则：串行、并行、条件分支何时使用。
- 依赖管理：哪些步骤必须前置，哪些可并发。
- 状态管理：每一步输出都要可记录、可回放。

## 建议的执行策略

1. 优先串行保证确定性，再逐步引入并发优化性能。
2. 对高风险写操作增加人工确认或双重校验。
3. 对每个子步骤定义超时和重试上限。

## 可靠性清单

- 关键流程是否具备幂等能力。
- 工具超时后是否有明确降级策略。
- 用户是否能看到“当前执行到哪一步”。
- 失败后是否可以从中间状态恢复。
