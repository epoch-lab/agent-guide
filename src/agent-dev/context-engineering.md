# 上下文工程

上下文工程的目标是“给模型足够信息做对事”，而不是“把所有信息都塞进去”。

## 四层上下文模型

1. **会话层**：当前用户意图、历史对话、目标约束。
2. **任务层**：任务状态、子任务结果、失败记录。
3. **知识层**：检索结果、业务规则、文档片段。
4. **运行层**：工具能力、权限范围、执行预算。

## 设计建议

- 先定义上下文优先级，避免无关信息污染推理。
- 用结构化片段（JSON/YAML）替代大段自由文本。
- 为每次响应记录“使用了哪些上下文”。

## 常见问题

- **上下文过长**：成本升高且核心信息被稀释。
- **上下文过旧**：模型基于陈旧状态做决策。
- **上下文冲突**：多个来源给出矛盾事实。

解决这些问题的关键是：分层管理、显式版本、可追溯。
